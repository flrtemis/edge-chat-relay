I could not move the binary. Two hard limits:
  - Drive downloads cap at 100 MB; EdgeChatRelay.exe is 162,917,276 B.
  - This sandbox cannot reach nuget.org, so `dotnet publish` fails and

Rather than fake it or skip it, .github/workflows/release.yml now
builds the self-contained single-file exe on a Windows runner and
attaches it to a GitHub Release, together with a SHA256 of the artifact.
Triggered by a v* tag or manual dispatch, and the JS tests must pass
before the build step in that job. The 163 MB file never touches the
Git tree, so the 100 MB limit is respected by construction.

Net effect versus "attach the local exe once": the published binary is
reproducible from tagged source and independently checksummed. Attaching
your prebuilt copy would have been faster but unverifiable.

Dependency to note: the workflow must be on `main` before it can run,
so the v1.2.0 release is a post-merge step, not something PR #1 can do.

If you specifically want the Drive binary published as-is, the path is:
create the release, upload the asset by hand (163 MB is fine for a
Release), and record md5 131408f95e69b87491fc79afe874397b (Drive's
checksum of the current EdgeChatRelay.exe, 2026-11-10 08:10) so the
asset can be tied back to the Drive copy.
